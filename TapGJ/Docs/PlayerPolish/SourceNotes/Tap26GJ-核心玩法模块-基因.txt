一、系统定位
基因系统是游戏的核心战斗构筑系统。玩家通过击败敌人或开启基因冷库获取基因，在同一条基因链内混合装配改造基因与属性基因。改造基因持续修饰基础子弹；属性基因按装配顺序由玩家主动触发附魔。玩家通过基因配置、轮换时机与战斗环境构筑不同的 Build。
核心游戏循环：
击败敌人 → 获取基因 → 装配基因链 → 构筑 Build → 挑战更强敌人
二、基因获取与成长
玩家通过击败敌人及开启基因冷库获取不同类型的基因。拾取后按基因ID记录至统一基因库存，供装配与进化使用。基因掉落规则与具体数值见本章，具体单个基因设计另行维护。
基因成长拟采用重复收集进化机制：
（1） 首次获得基因：解锁对应基因。
（2） 重复获得相同基因：累计进化进度。
（3） 达到指定数量：触发基因进化。进化影响该基因的等级和效果参数；是否开放进化分支待定。

四、基因链装配与运行
玩家将已获取的两类基因混合装配在同一条基因链中。所有已装配的改造基因持续影响子弹；只有属性基因参与主动附魔轮换。系统按原始槽位相对顺序提取属性基因，轮换期间自动略过改造基因。玩家仅能在“基因装配台”调整基因链的基因
运行规则：
待触发： 当前属性顺位处于就绪状态；不按右键时仍可发射受到常驻改造影响的基础子弹。
主动附魔： 玩家按鼠标右键，启动当前属性基因的附魔阶段；没有可用属性基因或重载未完成时无法启动。
持续生效： 附魔在指定时间内或指定射击次数内生效，发射的子弹同时获得全部常驻改造与当前属性。
顺位切换： 附魔阶段结束后，自动将下一条属性基因设为待触发；途中出现的改造基因不触发、不计数。玩家需要再次按右键开启下一属性阶段。
基因链重载：本轮所有已装配的属性基因阶段使用完毕后，进入统一重载状态；重载期间无法再次开启属性附魔，重载结束后回到首个属性基因。常驻改造在重载期间继续生效。
4.1 单链混合装配示意（规则示例，非具体基因设计）
槽位：改造A → 属性A → 改造B → 属性B。常驻改造集合={改造A、改造B}；属性轮换序列=[属性A、属性B]。
战斗：普通射击持续应用改造A与改造B；首次右键启动属性A阶段；结束后属性B就绪；再次右键启动属性B；结束后整链重载。
4.2 统一子弹执行流程
（1）按当前基础子弹模板生成子弹参数。
（2）叠加所有已装配改造基因：先合成数值参数，再绑定行为修改器；不同槽位顺序不改变常驻改造的执行优先级。
（3）如果当前属性附魔处于激活阶段，记录该属性至本次子弹实例；否则无额外属性附魔。
（4）子弹生成后固定本次属性与改造快照；后续属性换位、阶段结束、重载均不追溯修改已发射子弹。
（5）统一由子弹碰撞/生命周期系统处理命中、消失、范围效果及状态效果；递归生成、重复命中与触发上限需配置。
4.3 边界条件
（1）仅装配改造基因：改造持续生效，属性附魔无可触发项，不进入无意义的重载循环。
（2）仅装配一个属性基因：其附魔阶段结束后直接重载，不因略过改造基因而立即重复激活。
（3）存在空槽：轮换只处理实际装配的属性基因；空槽不触发附魔。
（4）重载中：普通子弹和常驻改造继续有效；是否允许打断重载及装配变化即时生效待定。
（5）时间型附魔、不同基因独立附魔次数、不同链长重载修正等进阶规则暂不纳入最小可玩版本。
4.4 待配置的通用参数
基因槽上限、属性附魔计数方式、每阶段可用次数/持续时间、基因链重载时间、击中状态持续时间、掉落概率、进化阈值等统一由配置表管理；未定数值不写死在代码中。

8.1 系统设计原则
基因系统采用数据驱动与模块化设计，将基因的管理方式、运行规则与具体能力执行分离，避免每种基因都需要独立编写一套子弹逻辑。
核心原则：
改造基因与属性基因共用一条固定槽位的基因链。
改造基因装配后常驻生效；属性基因按照装配顺序，由玩家通过鼠标右键主动触发。
基因效果尽量复用已有的子弹、碰撞、范围、状态及环境交互模块。
改造基因按照基因链从左到右的槽位顺序结算，优先于属性基因。
玩家只能在关卡内指定的基因编辑终端进行装配，不允许在其他位置直接打开装配界面。
基因进化与基因装配相互独立：进化在满足条件后立即结算，装配修改仅通过编辑终端完成。

8.3 基因管理层
8.3.1 GeneData（基因配置数据）
所有基因使用统一配置数据。
点击图片可查看完整电子表格
基因配置资源与玩家持有的基因实例数据分离，避免在获取、进化及装配过程中直接修改原始配置。
8.3.2 GeneInventory（基因库存管理器）
负责基因获取、库存记录、等级及进化管理。
基因库存需要区分以下标识：
GeneID：用于标识基因种类。
GeneInstanceID：用于标识玩家持有的具体基因实例。
基因获取与进化规则：
首次获得基因后，创建对应的初级基因记录。
累计获得3份相同初级基因后，自动进化为高级基因。
进化完成后，再次获得同名改造基因，不继续向已有高级基因累计进度，而是作为独立基因实例保留。
不同基因实例分别记录自身等级及进化状态。
允许玩家将同一种基因的不同实例重复装配。
基因进化在拾取并满足进化条件后立即结算，不要求玩家前往基因编辑终端。
8.3.3 GeneEditStation（基因编辑终端）
GeneEditStation 是玩家进入基因装配界面的唯一入口。
关卡中通过预先放置的指定交互装置提供装配功能。
运行规则：
玩家进入基因编辑终端的交互范围后，显示对应交互提示。
玩家按下E键，进入基因配置界面。
玩家未处于编辑终端的交互范围内时，按E键无法打开基因配置界面。
交互终端应布置在关卡预设的非战斗区域，避免玩家在战斗中直接调整构筑。
不采用玩家周围敌人距离检测作为装配权限的判断条件。
终端仅负责交互检测及打开装配界面，不直接处理基因效果和子弹逻辑。
装配修改与提交
为防止编辑过程中频繁修改实际战斗数据，装配界面采用临时配置与确认提交机制。
执行流程：
进入编辑终端 → 打开基因界面 → 修改临时装配方案 → 确认提交 → 更新实际基因链。
具体规则：
打开装配界面时，复制当前装配方案作为临时编辑数据。
玩家在界面中进行基因装入、替换、移除或调整顺序时，只修改临时数据。
玩家确认提交后，统一更新当前实际装配方案。
提交成功后，立即重新结算所有常驻改造基因和属性轮换队列。
玩家取消编辑或直接关闭界面时，未确认的修改不生效。
确认提交后，属性附魔状态重置为首个属性基因的待触发状态，避免新旧基因链运行状态冲突。
已发射子弹保留其生成时的效果快照，不受装配修改影响。
该方式使构筑阶段与战斗阶段分离，减少运行中修改基因所产生的特殊状态处理。
8.3.4 GeneChainController（基因链控制器）
负责管理当前装配方案、属性轮换、主动激活及整链重载。
玩家确认装配后，系统根据基因类型生成两个运行集合：
ModificationGenes：按原始槽位从左到右排列的全部改造基因。
AttributeQueue：按原始槽位从左到右排列的全部属性基因。
例如：
原始基因链：
改造A → 属性A → 改造B → 属性B
系统生成：
常驻改造集合：[改造A、改造B]
属性轮换队列：[属性A、属性B]
运行规则：
改造基因持续生效，不参与属性轮换。
属性轮换自动略过改造基因及空槽。
玩家按鼠标右键启动当前属性基因。
属性附魔统一按照持续时间结算，不采用发射次数结算。
当前属性阶段结束后，下一属性进入待触发状态，需要玩家再次按右键启动。
所有属性基因使用完毕后，整条属性链进入重载。
默认重载时间为3秒，通过配置表管理，支持后续调整。
重载期间无法启动属性附魔，但普通射击及常驻改造仍然生效。
不设置玩家主动跳过属性基因的功能。
若未装配属性基因，则不启动属性轮换及无意义的重载循环。
GeneChainController 只负责管理基因链运行状态，不直接执行具体子弹效果。
8.4 子弹执行层
8.4.1 BulletFactory / BulletEffectProcessor
负责根据基础子弹数据、当前改造基因以及属性附魔状态，生成最终子弹。
统一执行流程：
读取基础子弹模板。
按照基因链从左到右的槽位顺序，依次结算所有改造基因。
检查当前属性附魔是否处于激活状态。
若存在激活属性，则追加对应属性及效果配置。
保存本次子弹的独立效果快照。
生成并发射子弹。
改造基因优先于属性基因结算。
对于需要在命中、消失等后续事件触发的改造效果，同一触发事件中的处理顺序仍按照对应基因的原始装配顺序执行。
已经生成的子弹不受后续属性轮换、重载、基因进化或装配修改的追溯影响。

8.7 子弹继承与分裂代数控制
8.7.1 子弹继承规则
由改造效果额外生成的子弹，继承父弹生成时的属性及对应效果配置。
统一规则：
继承父弹的属性附魔快照。
继承已经结算完成的基础数值改造，不重复叠加改造数值。
额外生成的子弹拥有独立生命周期。
反弹次数由新子弹独立计算，不继承父弹已经消耗的反弹次数。
分裂次数由新子弹独立计算，但必须受到分裂代数限制。
子弹不会因后续基因链重载、属性切换或装配修改而改变自身已继承的属性。
8.7.2 分裂代数机制
为了防止子弹继承分裂能力后产生无限递归，采用分裂代数（SplitGeneration）机制。
每颗子弹记录以下运行数据：
点击图片可查看完整电子表格
执行规则：
玩家直接发射的原始子弹，分裂代数为0。
每生成下一代分裂子弹，其分裂代数增加1。
当前子弹代数大于或等于最大允许分裂代数时，不再触发分裂。
每颗子弹在自身生命周期内最多执行一次分裂事件。
子代继承最大分裂代数配置，但不继承父弹已经消耗的分裂次数。
同一次原始射击产生的全部子弹共享生成数量上限，防止多个分裂效果组合后造成生成数量失控。
第一版默认最大分裂代数为1。
即：
原始子弹（第0代） → 第一代分裂弹 → 结束。
第一代分裂弹可以正常执行继承的属性效果，但不可再次分裂。
该限制仅针对子弹生成行为，不限制属性状态与范围效果的正常重复触发。
8.8 通用掉落模块
DropService 统一负责敌人与基因冷库的奖励生成。
两类来源共用以下流程：
生成奖励 → 掉落物出现 → 玩家靠近 → 交互拾取 → 写入基因库存 → 显示获取反馈。
敌人及基因冷库仅通过掉落池、掉落数量与触发条件进行区分，不分别开发独立的基因拾取逻辑。
8.9 数据更新与生效规则
基因装配
玩家只能通过基因编辑终端修改装配。
确认提交后，立即更新实际基因链，并重新结算：
当前常驻改造基因集合；
当前属性基因轮换队列；
对应基因等级与效果参数；
属性轮换初始状态。
取消编辑时不更新实际装配数据。
基因进化
玩家获取基因后，若满足进化条件，立即完成进化结算。
进化不受基因编辑终端位置限制。若进化影响当前已装配的基因实例，后续新生成的子弹使用更新后的对应参数。
已经发射的子弹继续保留生成时的效果快照。

8.11 最终实现要求
基因装配只能通过关卡中指定的基因编辑终端进行，不采用随时按E打开或附近敌人距离检测的方案。
装配界面使用临时数据，玩家确认提交后才更新实际基因链。
装配提交后立即重新结算基因效果，并重置属性轮换状态。
基因获取与即时进化功能不受装配地点限制。
基因链控制器只管理装配、轮换、激活与重载，不直接执行具体子弹效果。
改造基因优先于属性基因，按照装配槽位从左到右的顺序结算。
每颗子弹保留生成时的独立效果快照。
额外生成的子弹继承属性效果，并使用分裂代数及生成总量上限避免无限递归。
新增基因优先通过现有公共能力模块和配置参数实现，仅在无法复用现有模块时扩展新的公共能力。
本系统优先完成“编辑终端装配 → 进入战斗 → 获取基因 → 即时进化 → 下一编辑终端重新构筑”的最小可玩循环，再逐步扩展高级基因与特殊机制。
